# Designing Challenges

You do not need to write code to propose a gameplay contribution.

Cybertruck Madness '98 currently supports an open procedural world rather than authored levels. Design proposals should work with the systems that already exist unless the proposal clearly identifies a new mechanic that needs implementation.

## Current design building blocks

You can design around:

- driving
- drift
- terrain height
- trees and rocks
- rings
- battery
- compass
- map
- extraction beacon
- mobile controls
- camera modes

## Good proposal types

### Driving route

Define a start area, route, landmarks and finish condition.

### Time trial

Define ordered checkpoints, expected duration and difficulty.

### Stunt challenge

Choose a terrain feature or proposed ramp location and define what counts as success.

### Ring route

Propose a ring pattern that creates a specific path or difficulty curve.

### Exploration challenge

Use landmarks, distance, battery pressure or navigation to create a route worth discovering.

### Accessibility change

Propose changes to controls, feedback, readability or navigation that make the game easier to use without changing the core identity.

## What to include

A useful proposal should include:

1. objective
2. start point or area
3. route or sequence
4. current mechanics used
5. difficulty
6. success condition
7. optional sketch, diagram or annotated screenshot

## Review

Large ideas should start as an issue before implementation.

A proposal is easier to review when it can be tested against the current game without requiring unrelated systems.

Accepted designs can be implemented by the original proposer or by another contributor.

The contribution should credit the design source in the pull request when implementation comes from someone else's accepted proposal.

Use the Design proposal issue template when submitting an idea.
